# SWOS Expanded 00.13.218 — Copa Bolivia: fixture sequence safe bridge (partial)

## Decision and scope

Approved: design a new format for sequences of matches, including interseries derbies, **without creating a second match engine**. Code now prepares an immutable 2026 4×4 + interseries group fixture sequence: 8 matchdays, 64 fixtures (48 within groups plus 16 cross-group); the eventual home/away knockout contributes 14 additional OG fixtures (78 total). Every one of the 16 clubs maps to an actual ordinal in `data_json/worlds/2627/teams/BOLIVIA.json`. Match IDs are 1–64 in the fixture builder; their future saved identity must contain world, edition and fixture ID. The template round/date order and exact first home-team assignments **have not been authenticated against every historical 2026 match**; these may not be called the real 2026 individual calendar yet.

## Code and files

- `sorgenti/include/bolivia_cup_sequence.h`: pure, deterministic fixture pair source, no RNG or result, 8×8 with guards against duplicate home/away identities. Group membership from July 22 real draw; reciprocal derby pairs from published regulations.
- `sorgenti/tests/test_bolivia_cup_sequence.c`, `sorgenti/tests/run_test_bolivia_cup_sequence.sh`: isolated C verification; linked into `sorgenti/tests/run_test_engine_suite.sh` and independent of gameplay.
- `sorgenti/src/career_init.c`: logs a preflight `[og-bolivia-format]` at first-year START; returns failure for invalid fixture template. **Does NOT schedule those matches**. Blocks old country45 table slot2 type1 national cup (its Mod 10 real + 6 bye draw was producing a fabricated ROUND OF 16 instead of the official groups).
- `sorgenti/src/career_status.c`: defense against legacy type1 execution; viewer reports `COPA BOLIVIA: OG GROUPS NOT RESIDENT` rather than showing fake results.
- `sorgenti/src/world_cups.c`: prevents manager joining the old type1 cup. This temporarily removes Copa Bolivia matches from the manager career rather than playing the wrong competition.
- `data_json/worlds/2627/competitions/copa_bolivia_2026_groups.json`: explicitly marks fixture sequence verified as static code only and `runtime_connected=false`.
- `sorgenti/include/build_info.h`: 00.13.218 (code changes, not merely docs).

## Real OG integration still required (NOT DONE)

1. Register native `CompetitionTournament` type2 country45/slot2 and ensure its exact first edition uses the 16 existing teams; do not cast the old `CompetitionCup` type1 memory layout as type2.
2. Map each authentic dated group fixture to the OG match executor; this fixture source MUST ONLY select pair/day, NEVER supply goal scores, calculate results or advance an independent clock.
3. Merge intra-group and interseries results in one standings context with OG result callbacks; top 2 of 4 groups to QF; 8+4+2 two-leg KO fixtures, OG champion/runner-up and qualification routing.
4. Share one resident state with unemployment/manager bind/unbind, no double results, read-only viewer and club match calendar.
5. Serialize complete resident state, RNG, dated per-fixture cursor and journal in the same compressed CAR; re-load from a separate process and verify fingerprints. Preserve existing 217 saves safely. Retain any unfinished edition across July even if it spans the year.
6. Authenticate the exact 2026 kickoff dates, venues/home leg order, actual draw and stage dates before advertising real calendar. Future editions derive entrants from proven OG competition results, not first-year fixed seeds.

The current resident country cup executor in `career_status.c::Expanded_OGWorld_AdvanceCup` requires `type==1`; only the continental `Expanded_OGWorld_AdvanceUefa` uses type2 in resident mode, and it is not a reusable national cup binding. `career_init.c::expanded_og_world_run_year` ignores non-type1 country cups. `Career_SetCurrentCompetitionSlot` restricts type2 career slots by selector and could PANIC if a type2 were casually inserted. `Expanded_OGWorld_YearEndCupResult` and the qualification code expect a type1 cup winner. Hence changing the record's type byte or generated `world_data.c` without extending these systems would corrupt fixture/save semantics. `world_data.c` itself is generated by `scripts/world_import.py`; do not hand-edit as a permanent definition.

## Why this approach

Fail-closed path: prevent made-up Copa Bolivia KO scores while preparing a format that OG can consume later. The alternative (mutate the legacy type1 header directly to type2 or run a parallel score generator) violates the single OG world requirement and can break saves and manager calendar. Trade-off: the cup remains unavailable for gameplay until its real type2 executor and CAR integration are complete. This is **partial work, not a completed Bolivia integration**; do not claim otherwise after this commit.
